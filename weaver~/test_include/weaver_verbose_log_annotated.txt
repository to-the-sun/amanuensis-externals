>>> ANNOTATION [WHY THIS OCCURS ONLY IN NEGATIVE TERRITORY]:
    Inside `weaver_process_vector` in `weaver~.c`:

    ```c
    long long latest_j = (end / (long long)bar_len) * (long long)bar_len;
    ```

    In C, when `end` (and thus `latest_j`) is negative, integer division truncates towards zero.
    For example, with a bar length of 2526 ms:
    - If `end = -2000`, then `-2000 / 2526 = 0` in C (truncation towards zero).
    - Therefore, `latest_j` becomes `0 * 2526 = 0`.
    - However, mathematically, floor division of `-2000 / 2526` is `-1`, so `latest_j` should be `-2526`.
    - Due to this truncation, `latest_j = 0` is returned.
    - Since `0` is greater than or equal to `start`, the condition `latest_j >= start` is continuously met on every single vector,
      causing the DSP thread to flood the FIFO queue with redundant triggers for the exact same bar (`bar 0`) over and over.
    - This is why the crossfades trigger immediately again after finishing, without waiting for the end of the bar!
